# 🛡️ Wireguard VPN:
## 📝 Введение

VPN — одно из ключевых решений для организации удалённого доступа. Будь то серверы в офисе, виртуальные машины в дата-центрах или ресурсы внутри локальной сети — всё это требует надёжного и управляемого подключения из дома.

## ❌ Проблема

Однако, при работе с VPN-серверами часто возникают проблемы с конфигурацией, особенно когда нужно развернуть несколько серверов со схожими, но не идентичными настройками. Например: разные локальные сети для разных филиалов, свои подсети, свои правила доступа.

## ✅ Решение

Чтобы упростить эту задачу, я решил организовать **централизованное управление конфигурациями**. Вместо того чтобы настраивать каждый сервер вручную или копировать конфиги с правками, я использовал подход **Infrastructure as Code (IaC)**.

В качестве инструмента был выбран **Ansible** — он позволяет описать желаемое состояние сервера в виде кода, а затем применить его к любому количеству машин.

Этот проект — моя реализация такого подхода для WireGuard с использованием популярной надстройки **wg-easy** (веб-интерфейс для управления VPN).

## ✨ Что умеет этот проект
- 🚀 Разворачивает VPN-сервер на основе `wg-easy`.
- 🌐 Настраивает iptables (разрешает поделючение к 51821 порту с локальных адресов только). Здесь нужно быть внимательным и осторожным с примененим
- 🔐 Генерирует и управляет WireGuard-ключами.
- 🖥️ Поднимает веб-интерфейс для управления клиентами.

## ⚙️ Требования к окружению
Проект протестирован и гарантированно работает в следующей конфигурации:

### 💻 На управляющем узле -Control Node (Место, откуда вы запускаете плейбук )
* **Ansible:** `2.16.3` (на этой версии велась разработка. Проверить свою версию: `ansible --version`).
* **Python:** `3.12.3`

### 🖥️ На целевых серверах (из hosts.ini)
* **ОС:** Ubuntu / Debian (плейбук настраивает конфигурацию для Linux систем).
* **Служба SSH:** На каждом сервере должен быть установлен и запущен `ssh-server`.
* **Доступ по ключу:** Управляющий узел должен подключаться к удаленным серверам по SSH-ключу без ввода пароля.
* **Права Ansible-пользователя:** Пользователь, под которым Ansible подключается к серверам (например, пользователь с правами sudo), должен иметь возможность выполнять команды с повышением привилегий (`become: true`) **без запроса пароля** (настройка `NOPASSWD` в sudoers на целевой машине). Это необходимо, так как проект управляет параметрами маршрутизации, правилами iptables для разрешающего трафика и установкой пакетов.

## 📂 Структура проекта
```text
.
├── roles/               # Директория с логикой автоматизации (роли)
│   ├── sysctl           # Роль для настройки forwarding
│   ├── docker_install   # Роль для установки docker
|   ├── wireguard        # Роль для развертывания и настройки VPN-сервера wg-easy
│   └── iptables         # Роль для настройки правил firewall    
├── hosts.ini            # Настройки подключения к вашим серверам
├── playbook.yml         # Главный файл для запуска всех ролей
└── requirements.yml     # Внешние роли и коллекции Ansible
```

## 🚀 Как запустить

1. **Клонировать репозиторий:**
```bash
git clone https://github.com/Vitaliy-Yashin/wg-easy.git && cd wg-easy
```
2. **Настроить инвентарь в hosts.ini:**
```ini
[public]
161.104.55.40 ansible_port=22 ansible_user=bob
[local]
192.168.92.147 ansible_port=22 ansible_user=vitaliy
```
3. **Установить зависимости**
```bash
ansible-galaxy install -r requirements.yml --force
```
4. **Настроить параметры для подключения к web ui:**

Отредактируйте файлы под свои цели в `roles/wireguard/vault/secret.yml` и для правил iptables `roles/iptables/vars/main.yml`.

🔒 Файл `roles/wireguard/vault/secret.yml` зашифрован в целях безопасности. Расшифровать его для редактирования можно следующей командой:
```bash
ansible-vault decrypt roles/wireguard/vault/secret.yml 
#Дефолтный пароль: 123456789
```
📝 После этого файл примет следующий вид, доступный для кастомизации:
```yaml
#roles/wireguard/vault/secret.ym
docker_env:
  host: "192.168.92.147" # Укажите адрес вашего vpn-сервера имитация публичного адреса
  password: "123456789" # Укажите пароль для web ui
  mtu: "1420" 
  default_address: "10.0.0.x" 
  allowed_ips: "192.168.0.0/24" # Укажите локальную сеть и ее маску подсети - в которой находится vpn-сервер   
  keep_alive: "25"
```

Отредактируйте также под себя файл `roles/iptables/vars/main.yml`
```yaml
#roles/iptables/vars/main.yml
destination_ip: "192.168.0.2" # Укажите локальный адрес vpn-сервера
destination_port: "51821" # Порт web ui
```

5. **(Опционально) Зашифровать файлы обратно:**
Сделайте это перед отправкой в Git. Используйте команду ниже и задайте свой собственный надежный пароль:
```bash
ansible-vault encrypt roles/wireguard/vault/secret.yml 
```
 
> ⚠️ **ВАЖНОЕ ПРИМЕЧАНИЕ ПО БЕЗОПАСНОСТИ (iptables):**
> Роль `iptables` настраивает сетевой экран так, что доступ к порту управления (`51821`) будет разрешен **только из локальной сети** (например, внутри офиса или уже после успешного подключения к самому VPN). 
> 
> Если вы настраиваете удаленный сервер впервые и находитесь вне его локальной сети, выполнение этой роли может заблокировать вам доступ к Web UI. 
>
> **Рекомендация:** При первом запуске рекомендуется временно закомментировать роль `iptables` в файле `playbook.yml`. Запустите плейбук без неё, убедитесь, что VPN работает и вы можете к нему подключиться, а уже затем примените правила сетевого экрана.

Для этого отредактируйте главный файл `playbook.yml`:
```yaml
# playbook.yml
  roles:
    - sysctl
    - docker_install
    - wireguard
    # - iptables  <-- Закомментируйте эту строку при первом запуске
```

6. **Запуск плейбука:**
* **🔓 Если файлы остались незашифрованными:**
```bash
ansible-playbook -i hosts.ini playbook.yml
```
* **🔒 Если файлы зашифрованы:**
```bash
ansible-playbook -i hosts.ini playbook.yml --ask-vault-pass 
#Укажите собственный пароль (или дефолтный "123456789", если вы его не меняли)
```
